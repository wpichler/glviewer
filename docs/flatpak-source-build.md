# Building GLViewer as a Flatpak from source

This describes what a Flatpak build of GLViewer needs. The project's own
manifest (`flatpak/io.github.wpichler.GLViewer.local.yml`) implements it and
is used for the release bundles.

**Flathub:** Flathub does not accept manifests that contain AI-generated or
AI-assisted content, and the local manifest was written with an AI agent. A
Flathub submission therefore needs a manifest written by the maintainer, and
the submission pull request must be opened and handled by a human. This
document lists the requirements; it intentionally does not contain a manifest.

## Runtime

* `org.freedesktop.Platform` / `org.freedesktop.Sdk` 26.08
* Base app `org.electronjs.Electron2.BaseApp` 26.08 (provides `zypak-wrapper`)
* SDK extension `org.freedesktop.Sdk.Extension.node22` for building

## Module 1: journalctl

The runtime contains `libsystemd` but no `journalctl`. Build it from the systemd
source tarball (same major version as current distributions, e.g. v262.x):

* Build dependency: Python `jinja2` + `markupsafe` (sdists from PyPI, put on
  `PYTHONPATH`; MarkupSafe has a pure-Python fallback).
* `meson setup` with `-Dmode=release -Dlink-journalctl-shared=false
  -Dtests=false -Dman=disabled -Dhtml=disabled -Dtranslations=false`, then
  `ninja journalctl` only.
* Install `journalctl` to `/app/bin`. The result links only against libc;
  compression libraries are loaded from the runtime at run time.
* Licenses: `LICENSE.GPL2`, `LICENSE.LGPL2.1` and the `LICENSES/` directory.

## Module 2: GLViewer

* Sources: the release tag (git) plus `flatpak/generated-sources.json`, which
  is generated by `flatpak-node-generator npm package-lock.json` and contains
  all npm packages and the Electron runtime zips (x86_64, aarch64).
* Environment: `XDG_CACHE_HOME=<builddir>/flatpak-node/cache`,
  `npm_config_cache=<builddir>/flatpak-node/npm-cache`, `npm_config_offline=true`,
  `ELECTRON_SKIP_BINARY_DOWNLOAD=1`.
* Build steps: `npm ci --offline --ignore-scripts`, `npx electron-vite build`,
  then `npx electron-builder --linux dir` with the architecture argument from
  `flatpak-node/electron-builder-arch-args.sh`.
* Install the unpacked app (`dist/linux*-unpacked`) to `/app/glviewer` and a
  launcher `/app/bin/glviewer` running `zypak-wrapper /app/glviewer/glviewer "$@"`.
* Desktop integration from the repository: `flatpak/io.github.wpichler.GLViewer.desktop`,
  `.metainfo.xml`, `.svg`, and `resources/icon.png` (512×512).
* Licenses: `LICENSE` (MIT, installed automatically by flatpak-builder) and
  Electron's `LICENSE.electron.txt` / `LICENSES.chromium.html`.

## Permissions and why they are needed

| Permission | Reason |
|---|---|
| `--share=ipc`, `--socket=wayland`, `--socket=fallback-x11`, `--device=dri` | GUI with GPU acceleration |
| `--share=network` | SSH connections to remote hosts; syslog receiver (UDP/TCP listener) |
| `--socket=ssh-auth` | Authentication with keys held by the user's SSH agent |
| `--filesystem=~/.ssh:ro` | Host list from `~/.ssh/config`, host key verification against `known_hosts`, key files; no portal exists for this |
| `--filesystem=/var/log:ro` | Browsing local log files and reading the persistent journal (`/var/log/journal`) with the bundled journalctl; no portal exists for this |
| `--filesystem=/run/log/journal:ro` | Volatile journal on systems without a persistent journal |

Other files are opened through the FileChooser / document portal (tested:
file dialog, "Open with", live follow, re-opening after restart).

Not requested: `--filesystem=host`, `--talk-name=org.freedesktop.Flatpak`.
Administrator access (`pkexec`) therefore is unavailable unless the user grants
host access.
